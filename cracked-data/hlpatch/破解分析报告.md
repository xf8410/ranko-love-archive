# hlpatch 仓库破解分析

## 仓库信息
- **仓库**：https://github.com/xf8410/hlpatch
- **描述**：赛马娘Android IL2CPP Hook插件 (Hachimi URA Plugin)
- **语言**：Rust + C++ (native)
- **构建系统**：Cargo + CMake

## 需要破解/解密的内容

### 1. libil2cpp.so (209MB, LFS)
- **状态**：已放入仓库 reverse/ 目录
- **加密方式**：Coneshell保护
- **破解方法**：需要运行时Frida hook绕过Coneshell，静态脱壳不可行
- **UmaDecryptor关联**：不适用（UmaDecryptor解密游戏数据文件，非SO保护）

### 2. global-metadata.dat (44MB, LFS)
- **状态**：已放入仓库 reverse/ 目录
- **加密方式**：IL2CPP标准混淆
- **破解方法**：使用Il2CppDumper + 对应版本的Unity元数据解密
- **UmaDecryptor关联**：不适用（UmaDecryptor处理的是游戏资源加密，非IL2CPP元数据）

### 3. master.mdb (42MB)
- **状态**：已放入仓库 reverse/ 目录
- **加密方式**：SQLCipher加密
- **破解方法**：✅ 可使用UmaDecryptor的decrypt-db命令解密
- **UmaDecryptor关联**：直接适用！UmaDecryptor专门为此设计

### 4. 游戏资源文件 (dat目录)
- **加密方式**：循环XOR（前256字节保持原样，从256字节开始XOR）
- **破解方法**：✅ 可使用UmaDecryptor的decrypt-dat命令解密
- **UmaDecryptor关联**：直接适用！

## UmaDecryptor解密算法分析

### 数据库解密 (SQLCipher)
```
DB_BASE_KEY = [0xF1, 0x70, 0xCE, 0xA4, 0xDF, 0xCE, 0xA3, 0xE1, 0xA5, 0xD8, 0xC7, 0x0B, 0xD1, 0x00, 0x00, 0x00]
日服密钥 (32字节) XOR DB_BASE_KEY[0:13] → 最终SQLCipher密钥
Global服密钥 (12字节) XOR DB_BASE_KEY[0:13] → 最终SQLCipher密钥
```

### 资源文件解密 (XOR)
```
BaseKeys = [0x53, 0x2B, 0x46, 0x31, 0xE4, 0xA7, 0xB9, 0x47, 0x3E, 0x7C, 0xFB]
Key = -7673907454518172050 (0x958F6B5A3D2E1C2E)

算法：
1. 将Key转为8字节小端
2. 对每个BaseKey字节：keys[i*8+j] = BaseKey[i] ^ keyBytes[j]
3. 得到88字节的keys数组
4. 跳过前256字节
5. data[i] ^= keys[i % 88]
```
